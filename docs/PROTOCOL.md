# MagerCam protocol v2

Телефон — сервер. ПК (программа для Windows, плагин OBS, браузер, VLC) — клиенты.

| Порт | Транспорт | Назначение |
|------|-----------|------------|
| 4848 | TCP (HTTP/1.0-подобный) | всё: веб-панель, MJPEG, API, бинарный поток |
| 4849 | UDP | автопоиск телефонов в локальной сети |
| 4850–4859 | TCP, **на ПК** | приём сопряжения по QR (слушает программа для Windows) |

По USB работает тот же TCP-порт через `adb forward tcp:<локальный> tcp:4848`.

Что изменилось с v1: код доступа, сопряжение по QR, H.265, профили, адаптивный битрейт, автокадрирование,
фон (размытие/картинка), запись на телефон, защита от перегрева, `POST /api/background`. Клиенты v1 работают
с телефоном v2, пока на нём выключен код доступа.

## Код доступа

Если в приложении включён код доступа (6 цифр), каждый запрос должен его нести:

- параметром `key=123456` в строке запроса, или
- заголовком `X-MagerCam-Key: 123456`.

Без кода или с неверным кодом телефон отвечает `401 Unauthorized`. После 10 неверных попыток с одного адреса
он минуту отвечает `429 Too Many Requests` на всё, даже на верный код.
Подключения с `127.0.0.1` (то есть по USB через `adb forward`) пропускаются без кода.

Клиенту стоит прекращать переподключения после 401/429 и спрашивать код у пользователя, иначе он сам выберет лимит.

## HTTP endpoints (порт 4848)

| Запрос | Ответ |
|--------|-------|
| `GET /` | Веб-панель управления |
| `GET /video` | MJPEG `multipart/x-mixed-replace` (браузер, VLC, OBS «Медиаисточник») |
| `GET /shot.jpg` | Один JPEG-кадр |
| `GET /api/status` | JSON-состояние (см. ниже) |
| `GET /api/set?k=v&k2=v2` | Изменить настройки, ответ — JSON-состояние |
| `POST /api/background` | Тело — JPEG/PNG до 12 МБ, картинка для замены фона. Ответ — JSON-состояние, `413` для пустого или слишком большого тела, `415` если это не картинка |
| `GET /stream?<params>` | Бинарный поток H.264/H.265 + PCM |

### Параметры `/stream` и `/api/set`

Все необязательные. Неизвестные игнорируются.

| Ключ | Значения | Живое изменение |
|------|----------|-----------------|
| `w`, `h` | разрешение, напр. `1920`,`1080` | перезапуск энкодера |
| `fps` | 15..60 | перезапуск энкодера |
| `bitrate` | кбит/с, 500..50000 — верхняя граница для адаптивного битрейта | на лету |
| `camera` | `back`, `front`, либо id камеры Camera2 | перезапуск энкодера |
| `audio` | `0`/`1` | на лету |
| `torch` | `0`/`1`/`toggle` | на лету |
| `zoom` | 1.0..max | на лету |
| `ev` | компенсация экспозиции в EV, -3..3 | на лету |
| `focus` | `continuous`, `auto`, `infinity`, `macro`, `manual` | на лету |
| `focus_dist` | 0..1 (0=бесконечность, 1=ближайший), для `manual` | на лету |
| `af` | `trigger` — однократная фокусировка; `x`,`y` (0..1) — точка | на лету |
| `wb` | `auto`, `daylight`, `cloudy`, `incandescent`, `fluorescent`, `shade`, `twilight` | на лету |
| `ae_lock`, `awb_lock` | `0`/`1` | на лету |
| `lock` | `0`/`1` — обе блокировки сразу (экспозиция и баланс белого) | на лету |
| `antibanding` | `auto`, `50`, `60`, `off` | на лету |
| `stab` | `0`/`1` — стабилизация видео | на лету |
| `mirror` | `0`/`1` — только превью/MJPEG на телефоне | на лету |
| `profile` | `call`, `stream`, `doc` — набор настроек сразу (см. ниже). Остальные параметры того же запроса применяются поверх | как у входящих в него ключей |
| `abr` | `0`/`1` — адаптивный битрейт | на лету |
| `codec` | в `/api/set`: `auto` (разрешить H.265) или `h264` (запретить). В `/stream`: `hevc` — клиент умеет H.265 | перезапуск энкодера |
| `framing` | `0`/`1` — автокадрирование: кадр плавно следует за лицом | на лету |
| `bg` | `off`, `blur`, `image` — размытие или замена фона | перезапуск энкодера |
| `bg_strength` | 0..1 — сила размытия / мягкость края | на лету |
| `rec` | `0`/`1` — запись MP4 на телефон (`Movies/MagerCam`) | на лету |
| `heat_guard` | `0`/`1` — снижать к/с и битрейт при перегреве | на лету |
| `key` | код доступа, см. выше | — |

Профили:

| `profile` | Что ставит |
|-----------|-----------|
| `call` | 1280×720, 30 к/с, 3 Мбит/с, фронтальная, автокадрирование, звук «голос» |
| `stream` | 1920×1080, 60 к/с, 12 Мбит/с, задняя, стабилизация, звук «видеокамера» |
| `doc` | 1920×1080, 30 к/с, 8 Мбит/с, задняя, без стабилизации и без обработки фона |

### H.265

Клиент добавляет `codec=hevc` в `/stream`, если у него есть декодер H.265. Телефон кодирует в H.265, только если:
кодер телефона это умеет (`"hevc": true` в статусе), пользователь не запретил (`codec_pref` ≠ `h264`)
и **все** подключённые к `/stream` клиенты попросили `hevc` — кодер у них общий.
Какой кодек сейчас идёт, видно по флагу в `VIDEO_CONFIG` и по полю `codec` в статусе.

### Адаптивный битрейт и перегрев

При `abr=1` телефон следит за очередью отправки: если она растёт или кадры приходится выбрасывать, битрейт
сразу падает на 30%, а после нескольких спокойных секунд постепенно возвращается к `bitrate`.
Текущее значение — `bitrate_now`.

При `heat_guard=1` и температуре батареи от 43.5 °C телефон ограничивает поток 30 к/с и 6 Мбит/с
(`"hot": true`), а ниже 40.5 °C снимает ограничение.

## Бинарный поток `/stream`

Клиент шлёт `GET /stream?... HTTP/1.1\r\n` (с `X-MagerCam-Key`, если нужен) и пустую строку.
Телефон отвечает `HTTP/1.1 200 OK\r\nContent-Type: application/x-magercam\r\n\r\n`, затем пакеты:

```
offset size  field
0      2     magic  'M','C'
2      1     type
3      1     flags  (bit0 = keyframe, bit1 = H.265 — только в VIDEO_CONFIG)
4      4     length (uint32 big-endian, размер payload)
8      8     pts    (int64 big-endian, микросекунды, общий таймлайн видео+аудио)
16     N     payload
```

| type | Имя | payload |
|------|-----|---------|
| 1 | VIDEO_CONFIG | H.264 SPS+PPS или H.265 VPS+SPS+PPS, Annex-B. Шлётся при каждом (пере)запуске энкодера; кодек может смениться посреди потока |
| 2 | VIDEO_FRAME  | access unit, Annex-B |
| 3 | AUDIO_CONFIG | uint32 BE sample_rate, uint8 channels (PCM s16le) |
| 4 | AUDIO        | PCM s16le interleaved |
| 5 | STATUS       | JSON (как `/api/status`), ~1 раз в секунду и при изменениях |
| 6 | PING         | пусто, ~1 раз в секунду если нет других данных |

После подключения нового клиента телефон запрашивает keyframe у энкодера.

## Автопоиск (UDP 4849)

ПК шлёт broadcast-датаграмму, начинающуюся с `MAGERCAM_DISCOVER`. Телефон отвечает unicast на адрес/порт
отправителя JSON: `{"magercam":1,"name":"Pixel 7","port":4848,"ver":2,"auth":true}`.

## Сопряжение по QR

1. Программа на ПК слушает TCP-порт из диапазона 4850–4859, придумывает одноразовый `nonce` и показывает QR с
   `magercam://pair?h=<IP ПК через запятую>&p=<порт>&n=<nonce>`.
2. Телефон сканирует код (кнопкой в приложении или системной камерой — ссылку откроет приложение),
   подключается к первому доступному адресу и шлёт:
   ```
   MCPAIR1 <nonce>\n
   {"name":"Pixel 7","ips":["192.168.1.23"],"port":4848,"key":"123456","ver":2}\n
   ```
   `key` пустой, если код доступа выключен.
3. ПК проверяет `nonce`, отвечает `OK\n` и подключается к телефону по адресу, с которого пришло соединение.
